# ATLA Editorial Completion Checklist

A chapter may be presented to the user as ready for review only when the applicable criteria have been checked against the exact latest version. A fixed number of turns or reviewer agreement is not proof of completion.

## A. Authority and baseline
- [ ] Latest PROJECT_STATE.md reconciled with the user's latest instruction.
- [ ] Correct target, branch, commit SHA, and workflow stage verified.
- [ ] REVISION_LEARNINGS.md, workflow instructions, and relevant authoritative sources consulted.
- [ ] Original/baseline version preserved or recoverable.
- [ ] No unapproved scope expansion.

## B. Developmental diagnosis
- [ ] Chapter purpose and intended reader effect identified.
- [ ] Opening, scene order, structure, causality, escalation, pacing, and ending assessed.
- [ ] Character agency, motivation, relationships, status dynamics, and emotional progression assessed.
- [ ] Fresh-eyes and beginner-reader comprehension assessed.
- [ ] ATLA canon, AU intent, worldbuilding, and chronology distinguished.
- [ ] Physical staging, action readability, injuries, objects, and consequences assessed where relevant.
- [ ] Effective material to preserve recorded.
- [ ] Revision strategy selected: targeted edit, substantial restructuring, scene rewrite, full rewrite, or no prose change.

## C. Revision integrity
- [ ] Every accepted material finding has a traceable change or documented disposition.
- [ ] Rejected findings have evidence-based reasons.
- [ ] Preferences are not represented as objective defects.
- [ ] No material change contradicts user decisions or authoritative sources.
- [ ] Complete chapter reread after latest material revision.
- [ ] Final diff inspected.
- [ ] No uncoordinated concurrent manuscript edits.

## D. Independent review
- [ ] Exact latest version sent to an independent reviewer after its latest material revision.
- [ ] Reviewer received exact commit/version identifier.
- [ ] Initial assessment was not anchored by Lead Editor conclusions.
- [ ] Reviewer role, platform, and actual independence limitations recorded.
- [ ] Findings verified rather than accepted automatically.
- [ ] Material disagreements and residual risks documented.
- [ ] A structural rewrite after review received a fresh whole-chapter review.

## E. Source and continuity verification
- [ ] Relevant canon sources checked directly where available.
- [ ] Intentional AU deviations preserved.
- [ ] Character knowledge and POV boundaries checked.
- [ ] Chronology, geography, physical continuity, and injuries checked.
- [ ] Relevant prior chapters and downstream dependencies checked.
- [ ] Supporting documents updated only where needed and remain consistent.
- [ ] Reusable lessons added only when supported and not duplicative.

## F. Repository and handoff
- [ ] Working branch and latest commit verified.
- [ ] Intended changes present; unintended files excluded.
- [ ] Commit, push, and PR status accurately reported.
- [ ] PROJECT_STATE.md reflects actual stage, work, blockers, and next action.
- [ ] Issue ledger reflects current dispositions.
- [ ] Any continuation checkpoint contains exact remaining work.
- [ ] No unsupported claim of tool use, agent delegation, external review, or verification.

## G. Ready-for-user decision
- [ ] No unresolved critical or major confirmed defect remains.
- [ ] Material plausible risks investigated or disclosed.
- [ ] No unresolved material issue can responsibly be fixed without user input.
- [ ] Final independent verification supports readiness.
- [ ] User report states changes, checks, limitations, and remaining issues.
